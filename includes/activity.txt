Meme-tastic OpenAI + Tidyverse Data Science Lab

Overview
- Theme: Use OpenAI’s API through the Tidyverse to generate meme-inspired captions and then analyze those captions with tidy data tools.
- Goal: Learn end-to-end API work in R (calls, error handling, parsing JSON), wrap results in a tidy workflow, and perform quick analyses and visualizations of the AI outputs.
- Audience: Graduate students familiar with R and the tidyverse (dplyr, tidyr, ggplot2, lubridate, purrr, etc.).
- Time: ~2–4 hours (can be split across two sessions).

Learning objectives
- Make HTTP API calls to OpenAI’s chat/completions endpoint from R.
- Handle API responses, errors, and usage data (tokens, model, timing).
- Build a tidy data pipeline: collect prompts, store responses in a tibble, and compute simple text metrics.
- Perform exploratory analysis and visualization of AI-generated content.
- Practice reproducible workflow hygiene: environment variables for API keys, saving results, and documenting assumptions.

Prep and setup
- Prerequisites: R (4.x), an OpenAI API key.
- Install packages (one-time):
  - install.packages(c("httr", "jsonlite", "tidyverse", "purrr", "stringr", "tidytext"))
  - Optional for sentiment: install.packages("textdata") and use tidytext lexicons.
- API key: store securely and load via environment variable OPENAI_API_KEY (e.g., in .Renviron or using Sys.setenv in session).
  - Example: Sys.setenv(OPENAI_API_KEY = "YOUR_API_KEY_HERE")
- OpenAI API basics: we'll use the chat/completions endpoint to send a user message and receive a content string.

Step-by-step activity

1) Define the meme-themed prompts
- Create a small, diverse set of prompts to generate meme captions or short memes about data science.
- Example prompts (store in a tibble):
  - "Caption a data science meme about overfitting."
  - "Explain gradient descent as a meme."
  - "Debugging code described as a detective noir caption."
  - "Summarize the data science workflow in exactly 9 words as a meme."

2) Build a reusable API call function (OpenAI Chat Completions)
- Core idea: send a prompt to the API and return the AI's message content plus usage data.

R code sketch (httr + jsonlite)
- Important: do not print your API key; rely on the environment variable OPENAI_API_KEY.

- Load libraries
  library(httr)
  library(jsonlite)
  library(tidyverse)

- Helper function to call the API (chat/completions)
  call_openai_chat <- function(prompt, model = "gpt-4", temperature = 0.7, max_tokens = 200) {
    req <- POST(
      url = "https://api.openai.com/v1/chat/completions",
      add_headers(Authorization = paste("Bearer", Sys.getenv("OPENAI_API_KEY"))),
      content_type_json(),
      body = toJSON(list(
        model = model,
        messages = list(list(role = "user", content = prompt)),
        temperature = temperature,
        max_tokens = max_tokens
      ), auto_unbox = TRUE)
    )
    stop_for_status(req)
    res_txt <- content(req, as = "text", encoding = "UTF-8")
    res <- fromJSON(res_txt, flatten = TRUE)
    list(
      content = res$choices[[1]]$message$content,
      model = res$model,
      used = res$usage
    )
  }

- Batch call helper that returns a tidy row per prompt
  call_and_wrap <- function(prompt) {
    r <- call_openai_chat(prompt, model = "gpt-4", temperature = 0.7, max_tokens = 200)
    tibble(
      prompt = prompt,
      response = r$content,
      model = r$model,
      prompt_tokens = r$used$prompt_tokens,
      completion_tokens = r$used$completion_tokens,
      total_tokens = r$used$total_tokens
    )
  }

3) Run prompts and collect results
- Create a data frame of prompts (one row per prompt) and then map the API call function to each.

R code sketch
  prompts <- tibble(
    id = 1:4,
    prompt = c(
      "Caption a data science meme about overfitting.",
      "Explain gradient descent as a meme.",
      "Debugging code described as a detective noir caption.",
      "Summarize the data science workflow in exactly 9 words as a meme."
    )
  )

  # Execute API calls for all prompts and combine results
  results_df <- prompts %>%
    mutate(res = map(prompt, ~ call_and_wrap(.x))) %>%             # or use purrr::map_df
    unnest(cols = c(res))

- Quick note: in a real session, consider adding tryCatch to handle rate limits or transient errors. You can also batch requests with pauses to respect rate limits and avoid throttling.

4) Clean and parse the responses
- Compute simple text metrics and store in the tibble
  - Word count, sentence count, and a rough "meme score" (e.g., presence of meme-related keywords).
  - Optional: basic sentiment using tidytext and a Bing lexicon.

R code sketch
  library(stringr)
  library(tidytext)

  results_df <- results_df %>%
    mutate(
      word_count = str_count(response, "\\w+"),
      sentence_count = str_count(response, "[.!?]"),
      # simple keyword check for meme vibes (case-insensitive)
      meme_keywords = str_count(tolower(response), "(caption|captioned|meme|overfitting|gradient|noir|case|workflow|neural|training)"),
      # rough sentiment score using Bing lexicon (positive = +, negative = -)
      sentiment_score = {
        toks <- tibble(text = response) %>%
          unnest_tokens(word, text)
        bing <- get_sentiments("bing")
        s <- toks %>% inner_join(bing, by = "word")
        if (nrow(s) == 0) 0 else sum(ifelse(s$sentiment == "positive", 1, -1))
      }
    )

5) Analyze and visualize
- Quick summaries:
  - Compare prompts by mean word_count or mean meme_keywords count
  - Inspect which prompts tend to produce longer captions or more positive/negative sentiment
- Visualization ideas:
  - Bar chart of average word_count by prompt
  - Dot plot of meme_keywords by prompt
  - A sentiment bar chart by prompt

R code sketch
  library(ggplot2)

  # Summary by prompt
  summary_by_prompt <- results_df %>%
    group_by(prompt) %>%
    summarize(
      mean_words = mean(word_count, na.rm = TRUE),
      max_words = max(word_count, na.rm = TRUE),
      mean_meme_keywords = mean(meme_keywords, na.rm = TRUE),
      mean_sentiment = mean(sentiment_score, na.rm = TRUE),
      n = n()
    )

  # Plot: average word count per prompt
  ggplot(summary_by_prompt, aes(x = reorder(prompt, mean_words), y = mean_words)) +
    geom_col(fill = "steelblue") +
    coord_flip() +
    labs(title = "Average word count by meme prompt",
         x = "Prompt",
         y = "Average word count")

  # Plot: meme keyword density per prompt
  ggplot(results_df, aes(x = prompt, y = meme_keywords)) +
    geom_jitter(width = 0.2, height = 0, alpha = 0.6) +
    coord_flip() +
    labs(title = "Meme keyword density by response",
         x = "Prompt",
         y = "Meme keyword occurrences")

  # Optional: sentiment per prompt
  sentiment_by_prompt <- results_df %>%
    group_by(prompt) %>%
    summarize(mean_sentiment = mean(sentiment_score, na.rm = TRUE))

  ggplot(sentiment_by_prompt, aes(x = reorder(prompt, mean_sentiment), y = mean_sentiment)) +
    geom_col(fill = "tomato") +
    coord_flip() +
    labs(title = "Average sentiment by prompt",
         x = "Prompt",
         y = "Mean sentiment score")

8) Best practices and tips
- API key handling: never hard-code keys; keep them in environment variables or .Renviron.
- Rate limits: batch requests where possible and insert small pauses if you’re calling many prompts.
- Reproducibility: seed any random components, save the results as CSV/Parquet, and provide a small readme with a reproducible script.
- Documentation: annotate each step in your notebook with the learning objective it addresses (e.g., “API call and response parsing,” “tidy data wrangling,” “text analysis”).
