Here’s a ready-to-use, meme-tastic data science activity for grad students to learn how to use OpenAI’s API from within a Tidyverse workflow. It guides students through API calls, response handling, and analysis of the results, all wrapped in a fun meme-inspired prompt bank.

Learning objectives
- Build and call OpenAI’s Chat Completions API from R (without relying on a dedicated OpenAI package).
- Handle API responses robustly (parse JSON, extract content, capture usage metrics, manage errors and rate-limits).
- Integrate OpenAI outputs into a tidyverse workflow: store prompts and responses in data frames, compute simple text analytics, and visualize results.
- Practice prompt engineering with meme-style prompts to explore tone, length, and informativeness.
- Reflect on model behavior, cost considerations, and reproducibility.

Prerequisites and setup
- R installed (>= 4.0 recommended).
- Packages: tidyverse, httr, jsonlite, purrr, stringr, readr, ggplot2 (part of tidyverse), lubridate (optional for timestamps).
- An OpenAI API key. Set it as an environment variable OPENAI_API_KEY (recommended) or store securely and read in code.
- Optional but helpful: a local notebook or RMarkdown document to collect results and visuals.

Estimated time
- 2–4 hours, depending on depth of analysis and how many prompts you extend.

What students will produce
- A tibble with prompts, responses, usage metrics (prompt_tokens, completion_tokens, total_tokens), and timestamps.
- Simple text analyses: word counts, estimated readability proxies, and a couple of memes-as-outputs visualizations.
- A short reflective write-up comparing prompts (tone, length, usefulness) and discussing model behavior.

Activity outline (three main parts)
1) Prompt bank design (meme-tastic prompts)
2) API calls and response handling
3) Analysis, visualization, and interpretation

Part 2 — API calls and response handling (step-by-step with code)
All code here uses base R with tidyverse and httr/jsonlite for API access. Students should run these in an R session or R Markdown.

1) Load libraries and set API key
- Add to R script:
  library(tidyverse)
  library(httr)
  library(jsonlite)
  library(purrr)
  library(stringr)

  # Get API key from environment variable
  api_key <- Sys.getenv("OPENAI_API_KEY")
  if (api_key == "" || is.na(api_key)) {
    stop("OPENAI_API_KEY environment variable not set. Set it before running the lab.")
  }

2) Define a safe API call function
- Add to R script:
  call_openai <- function(prompt, model = "gpt-3.5-turbo",
                         system_msg = "You are a witty data-science meme bot. Produce concise, meme-ready captions with a touch of data insight.",
                         max_tokens = 512, temperature = 0.7) {
    body <- list(
      model = model,
      messages = list(
        list(role = "system", content = system_msg),
        list(role = "user", content = prompt)
      ),
      max_tokens = max_tokens,
      temperature = temperature,
      top_p = 1
    )

    res <- httr::POST(
      url = "https://api.openai.com/v1/chat/completions",
      httr::add_headers(Authorization = paste("Bearer", api_key)),
      httr::content_type_json(),
      body = jsonlite::toJSON(body, auto_unbox = TRUE)
    )

    if (httr::status_code(res) != 200) {
      stop("OpenAI API error: ", httr::content(res, as = "text", encoding = "UTF-8"))
    }

    parsed <- jsonlite::fromJSON(httr::content(res, as = "text", encoding = "UTF-8"), flatten = TRUE)

    # Pull response text and usage metrics
    response_text <- parsed$choices[[1]]$message$content
    usage <- parsed$usage
    tibble::tibble(
      prompt = prompt,
      response = response_text,
      model = parsed$model,
      created = as.integer(parsed$created),
      prompt_tokens = as.integer(usage$prompt_tokens),
      completion_tokens = as.integer(usage$completion_tokens),
      total_tokens = as.integer(usage$total_tokens)
    )
  }

3) Build a prompt table (your meme prompts)
- Add to R script:
  prompts <- tibble(
    id = 1:6,
    category = c("Data Cleaning", "Model Misinterpretation", "Visualization", "Prompt Engineering", "Ethics", "Quick Tip"),
    prompt = c(
      "You are the meme lord of data science. Generate a 3-panel meme caption about cleaning a messy dataset, in Doge/Distracted Boyfriend style. Include a punchline and one data tip in the last panel.",
      "Explain a common data science mistake as a meme caption. Use a witty, sarcastic tone.",
      "Create a short meme caption about choosing a plot type for a dashboard, with a punchline and a one-sentence justification.",
      "Give a concise, meme-style guide to prompt engineering for reliable AI responses in R, fit for a slide gutter.",
      "Summarize an ethical concern in data science as a meme caption and pair with a one-line mitigation tip.",
      "Provide a two-sentence meme caption that communicates a best-practice for reproducible workflows in R/Tidyverse."
    )
  )

4) Call the API for all prompts and combine results
- Add to R script:
  results <- prompts %>%
    mutate(res = map(prompt, ~ call_openai(.x))) %>%     # call API for each prompt
    unnest(res)

- What you get: a tibble with columns prompt, response, model, created, prompt_tokens, completion_tokens, total_tokens, etc.

5) Quick text analytics and tidy visualization
- Compute word counts and basic structure
  results <- results %>%
    mutate(
      word_count = str_count(response, boundary("word")),
      sentence_count = str_count(response, "[.!?]"),
      avg_words_per_sentence = ifelse(sentence_count > 0, word_count / sentence_count, NA_real_)
    )

6) Visualizations (example)
- Plot 1: Total tokens per prompt
  ggplot(results, aes(x = reorder(category, total_tokens), y = total_tokens, fill = category)) +
    geom_col(show.legend = FALSE) +
    coord_flip() +
    labs(title = "OpenAI token usage by meme prompt category",
         x = "Prompt category",
         y = "Total tokens (prompt + completion)")

- Plot 2: Word count per prompt

Part 3 — Analysis, interpretation, and discussion
Guided questions students can address in a short write-up or discussion:
- Which prompts produced longer responses, and why might that be?
- Do meme-style prompts influence clarity or usefulness? Are some prompts more entertaining but less informative?
- How does temperature setting affect the humor or precision of responses? Try re-running a few prompts with different temperatures.
- How do usage metrics (prompt_tokens, total_tokens) relate to response quality? Is there an optimal range?
- What are reproducibility considerations when using the API in research or teaching labs?
- How would you adapt prompts for different audiences (experts vs. beginners)?

Optional extensions (stretch goals)
- Experiment with different models (gpt-3.5-turbo vs gpt-4-turbo if available) and compare outputs and token usage.
- Build a function that can batch-call the API with a vector of prompts and return a tidy dataframe without unnesting manually.
- Integrate sentiment or humor scoring (e.g., simple keyword scoring for humor tokens) and compare across prompts.
- Create a reusable R Studio/Addin that lets students click a button to send a highlighted prompt to the API and insert the response back into the script as a comment or tibble.

Quality checks and best practices
- Rate limits and retry: If you anticipate many calls, insert a delay (Sys.sleep(1) or Sys.sleep(sample(1:2, 1))) between calls to respect rate limits.
- Costs and constraints: Set a conservative max_tokens and temperature; consider using the free or a capped API tier and track total_tokens for cost awareness.
- Security: Do not hard-code API keys in scripts. Use environment variables or secure vaults. Do not share API keys in public repos.
- Reproducibility: Save prompts and responses to a dedicated results/ directory (CSV/Parquet) with a date stamp. Use set.seed if you’re generating any random elements for plots.

Deliverables for submission or presentation
- A clean R script or R Markdown notebook containing:
  - The prompt bank (as a tibble).
  - The API call function and a loop/apply call to fetch responses.
  - A tidy dataframe of results with computed metrics.
  - At least two visuals (e.g., token usage by category, response length by category).
  - A short interpretation section or slide-ready notes summarizing observations and takeaways.
- A one-page reflection on what the meme prompts reveal about model behavior and how you’d use similar prompts in your own projects.

Safety and ethics brief
- Be mindful of copyright and attribution if you quote or analyze content produced by the model.
- Do not rely on model outputs as professional or legal advice; clearly communicate model limitations.
- Respect data privacy and do not feed sensitive or proprietary data into the model.
